SIEVE

An eviction algorithm simpler than LRU, for web caches

One queue, one pointer and one bit per object. A hit only sets a bit, so it takes no lock, and replacing LRU with SIEVE in a cache library takes about 20 lines of code.

How it works

A hand that sifts one queue

New objects join the head of a single queue. When the cache is full, a hand walks from the tail toward the head: objects that were used since it last passed keep their place, and the first one that was not is evicted.

  1. 1 queue

    New objects go in at the head

    Objects stay in the order they arrived. Nothing is ever moved back to the head, so the queue never needs reordering.

  2. 1 bit

    A hit sets one bit

    A hit marks the object as visited. If the bit is already set there is nothing to do at all: no lock and no pointer updates on the hot path.

  3. hand

    The hand sifts

    To make room, the hand walks from the tail toward the head, clearing the bits of visited objects, and evicts the first one that was not visited. Past the head, it wraps back to the tail.

  4. vs CLOCK

    Survivors stay put

    CLOCK moves a surviving object back to the head with the new ones. SIEVE leaves it where it is, so popular objects settle near the tail and new ones that are not reused leave quickly.

Use it

The whole algorithm fits on a card

Pick a library in your language, or replay your own traces against SIEVE in libCacheSim.

SIEVE, in pseudocode 
# request x, queue T, size C, hand p
if x in T:                       # hit
    x.visited = true
else:                             # miss
    if |T| == C:                   # cache full
        obj = p or tail(T)
        while obj.visited:
            obj.visited = false
            obj = obj.prev or tail(T)
        p = obj.prev
        discard obj                    # eviction
    insert x at head(T)
    x.visited = false               # insertion
